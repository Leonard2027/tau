装配阶段：程序启动时

这一阶段还没有模型调用任何工具。

产品层 executor 真正的读文件、运行 shell 逻辑。属于 tau_coding，知道 cwd、路径处理、输出截断等产品策略。
AgentTool provider-neutral 插头：名称、schema、executor、renderer 与声明性元数据。属于 tau_agent。
AgentHarness 持有 list[AgentTool]、消息历史、取消令牌、队列、hooks 和 listeners。

运行阶段：模型请求工具

完整执行链

UserMessage("读取 README.md")
  ↓ provider.stream_response(...)
AssistantMessage(content=[ToolCall(id="call-1", name="read")])
  ↓ loop 按 name 查找；进入 _execute_tool_call
ToolExecutionStartEvent                         # 表示开始处理请求
  ↓ before_tool_call(call)                      # 可阻止
  ↓ cancellation check / unknown-tool check
  ↓ AgentTool.execute(..., signal, on_update)   # 产品 executor
  ↓ ToolExecutionUpdateEvent*                   # 可选进度
  ↓ Exception → 标准错误结果；CancelledError 重抛
  ↓ after_tool_call(call, result, is_error)     # 结果治理
ToolExecutionEndEvent
  ↓ loop 包装
ToolResultMessage(tool_call_id="call-1", tool_name="read")
  ↓ 放回消息历史
模型根据工具结果生成最终 AssistantMessage

ToolCall

模型发出的请求

assistant content block，不是顶层消息。包含 id、name、arguments。

AgentTool

系统注册的可执行契约

loop 以 ToolCall.name 查找；真正副作用由产品层 executor 完成。

AgentToolResult

executor 的运行时结果

还不是对话消息，包含标准 content、details 与可选 added tools。

ToolResultMessage

写入历史的顶层消息

通过 tool_call_id 关联原始 call，并保留 tool_name 与 is_error。

事件语义：ToolExecutionStartEvent 表示 runtime 开始处理请求，不证明 executor 已运行；被 policy gate 拒绝的调用也会先出现 start，随后以标准错误 end/result 收束。

取消与中断修复

协作式取消

令牌需要各层观察

harness.cancel() 设置 cancellation token。provider 可停止流式输出，loop 在工具前检查，长运行工具还要主动观察 token。

Bash 特例

等待进程或取消先完成

bash 用 asyncio.wait(..., FIRST_COMPLETED) 同时等待进程和取消；POSIX 下以新 session 启动并用 os.killpg 杀掉整个 process group。

孤儿 tool call 的补偿记录

如果 AssistantMessage 已包含 ToolCall，但历史中没有相同 ID 的 ToolResultMessage，Harness 追加：

ToolResultMessage(
    tool_call_id=call.id,
    tool_name=call.name,
    content=[TextContent(text="Tool call interrupted by user")],
    is_error=True,
)

修复发生在三个时机：新 prompt_message() 前、continue_() 前，以及已观察到取消时的 _run() finally。入口修复也覆盖从持久化日志或旧版本加载的历史。

src/tau_agent/harness.py:146–190, 219–244

Completeness

每个 call 都有终态

成功结果或明确错误结果都会闭合 ToolCall.id。

Idempotency

重复修复不重复追加

returned_ids 使已有结果的 call 被跳过。

Auditability

不删除发生过的请求

保留“模型请求过工具，但执行未完成”的事实。

Replayability

恢复后可继续

完整 call/result 配对避免 provider 面对悬空请求。

补偿，不是重试：中断结果只声明这次调用没有成功完成，不会重新执行工具。对邮件、扣款、文件写入或部署等有副作用的工具，盲目重试可能重复执行。

工具安全：已有 seam 不等于完整沙箱

已有 · Authorization seam

执行前可以阻止

before_tool_call 接收完整 call，适合由 host 注入权限、审批和高风险参数策略；被拒绝后仍写回标准错误结果。

已有 · Error boundary

普通异常被归一化

executor 的普通 Exception 变成 AgentToolResult + is_error=True；asyncio.CancelledError 特意重抛。

已有 · Result governance

执行后统一处理

after_tool_call 可处理成功、blocked、cancelled、unknown-tool 和 exception 路径，适合脱敏和统一结果包装。

空缺 · Generic timeout

loop 没有 per-tool deadline

核心 loop 没有统一 timeout；具体工具可自行实现（如 bash 的可选 timeout），其他工具需 executor wrapper 或独立 runner。

空缺 · Process isolation

异常边界不是资源沙箱

Python 异常归一化不会限制文件、网络、CPU、内存或系统调用。高风险执行需要受限进程、容器或独立服务。

受信任边界 · Hooks

policy code 自己也会失败

hooks 的异常不在 _execute_tool_call 内归一化。host 必须决定依赖故障时 fail-open 还是 fail-closed，并处理 hook 自身错误。

Canonical failures：已取消是 Operation aborted；未知工具是 Tool <name> not found。这些路径和 blocked/exception 一样，最终形成 ToolExecutionEndEvent 与 ToolResultMessage。

并发模型

当前执行拓扑

AgentHarness
  │  同时只允许一个 active run (single-flight)
  │
  └── run_agent_loop (async generator)
        │  顺序消费 provider stream
        │  按 for call in calls 顺序执行 ToolCall
        │  顺序产生 AgentEvent
        │
        └── 具体工具内部可以自行并发
              └── bash: process.communicate vs cancellation
                    → FIRST_COMPLETED
                    → timeout/cancel 时 kill process group
声明 ≠ 调度

execution_mode

AgentTool.execution_mode="parallel" 是声明性元数据；当前 run_agent_loop 没有读取它，多个 calls 仍顺序执行。

工具内并发

由具体 executor 实现

bash 的 task 竞争属于工具内部生命周期管理，不代表 loop 会并行调度多个工具。

Steering 与 Follow-up 队列

Steering

运行中插入

harness.steer(...) 的消息在下一轮工具完成后、下一次 provider 调用前注入，用于及时干预。

Follow-up

自然结束后追加

harness.follow_up(...) 在当前 run 自然结束后触发新一轮，用于排队的后续任务。

队列排水模式

queue_mode="one_at_a_time"  → 每轮只取一条
queue_mode="all"            → 每轮全部取出

src/tau_agent/harness.py:204–217 · src/tau_agent/loop.py:83, 160–166

队列不是并行任务：它们是等待进入同一 loop 的消息，不是同时运行的多个 agent run。

事件订阅与背压

顺序通知，自然背压

for listener in listeners:
    result = listener(event)
    if isawaitable(result):
        await result

Harness 先逐个等待 listeners，再把同一事件 yield 给主迭代者。async generator 也是拉取式的，因此慢 listener 或慢主消费者都能延迟 loop，最终让 provider stream 暂停推进。

src/tau_agent/harness.py:169–196

面试要点

  1. Loop vs Harness：loop 不拥有跨 run 持久状态，但单次 generator frame 仍有 turn/pending，并修改传入的 messages；Harness 管理跨 run 历史、生命周期、队列、取消和订阅。
  2. 安全 gate：授权应优先放在 before_tool_call，而不是 provider 或 renderer；after_tool_call 负责受信任的结果治理。
  3. 保证与空缺：标准错误结果和 hooks 是机制，不等于 timeout、租户隔离或进程沙箱；这些仍由 host/execution layer 提供。
  4. 两种 result：AgentToolResult 是 executor 返回值；ToolResultMessage 是写入消息历史的协议记录。
  5. 中断修复：孤儿 call 追加幂等的错误结果，以满足 completeness、auditability 与 replayability；这是补偿，不是重试。
  6. 顺序执行：当前 loop 按 for call in calls 顺序执行；execution_mode 未参与调度。
  7. 背压：listeners 顺序 await，主路径按 async iterator 拉取；慢消费者会把延迟向 provider 传播。
