核心怎样做到不知道具体模型厂商？

本节只研究一条架构 seam：run_agent_loop 不认识 Anthropic、OpenAI 或本地模型，它只认识 ModelProvider 协议。

先预测 源码切片 接口练习 完整路线

0–3 分钟：先预测替换边界

假设现在使用远程模型，明天要换成本地模型。为了让 run_agent_loop 完全不用修改，模型适配器必须向核心稳定提供什么？

先写下：它需要接收哪些信息，以及应该以什么形式返回模型响应。

3–10 分钟：只读一个 Protocol

src/tau_agent/provider.py:13–32

Cancellation contract

CancellationToken

核心只要求一个 is_cancelled() → bool 能力。它不要求 provider 知道 UI 上的“停止按钮”或进程信号来自哪里。

Provider contract

ModelProvider

任何对象只要提供符合签名的 stream_response(...)，就可以站在 provider seam 后面；loop 依赖这个能力，而不是具体实现类。

输入：一次模型生成所需的 provider-neutral 上下文

  • model: str — 选择哪个模型。
  • system: str — 系统指令。
  • messages: list[AgentMessage] — 已有对话历史。
  • tools: list[AgentTool] — 模型可请求的工具契约。
  • signal: CancellationToken | None — 可选取消信号。

输出：统一的流式响应

AsyncIterator[AssistantMessageEvent]。具体 SDK 的 chunk、字段名和传输方式必须在 provider 实现内部转换为 tau_agent.provider_events 定义的统一事件。

src/tau_agent/loop.py:189–223

调用方向：loop 调用 provider.stream_response(...)，再把统一的 provider events 转成更高层的 agent message events。依赖方向是“具体 provider 实现依赖核心协议”，而不是核心反过来依赖厂商 SDK。
仓库证据：tests/test_pi_event_protocol.py:32–36 会扫描整个 src/tau_agent，确保它没有导入 tau_ai。

方法：stream_response()。

输入：model、system、messages、tools、signal。

输出：AsyncIterator[AssistantMessageEvent]。

转换位置：具体 provider adapter 内部；tau_agent 只消费统一事件。

14–15 分钟：一句话检索

run_agent_loop 不依赖具体厂商，而是依赖 ______；具体适配器把厂商流转换成 ______。
面试表达：这是一条依赖倒置边界：高层 agent loop 定义它需要的最小协议，低层厂商适配器实现该协议。
