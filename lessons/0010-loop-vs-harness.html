Micro lesson 10 · Agent platform interview · About 15 minutes

为什么同时需要无状态 loop 与有状态 harness？

这不是把代码随意拆成两个文件，而是把“单次运行的确定性算法”与“跨运行的状态和策略”放在不同部署边界。目标是能从职责、测试性与平台扩展三个角度解释这项设计。

先预测 对象追踪 架构比较 面试练习 完整路线

0–3 分钟：先做架构预测

假设 Tau 删除 AgentHarness，把 _messages、_running、取消令牌、steering/follow-up 队列和 listeners 全部塞进 run_agent_loop。

先预测：这样做最先会损害下面哪一项？为什么？

  1. 模型回答质量
  2. 核心算法的可复用与可测试性
  3. 工具 schema 的表达能力

不要只说“耦合更高”；试着指出一种具体测试或宿主实现会因此变难。

3–7 分钟：追踪一个事件穿过两层边界

src/tau_agent/loop.py:44–168 · src/tau_agent/harness.py:146–202

run_agent_loop 根据传入参数执行一次 run，以 yield event 暴露进度；不保存下一次 run 所需的宿主状态。
AgentHarness._run 把自身持有的消息、队列回调和取消令牌注入 loop；逐个接收事件。
外部消费者 listener 先收到广播；迭代 prompt() 的调用方随后收到同一事件。

关键执行顺序

async for event in run_agent_loop(...):
    await self._notify(event)   # subscription port；逐个等待 listener
    yield event                 # return port；交给 prompt() 的迭代调用方

async generator 是拉取式的：下游请求下一项时，上游才继续推进。Tau 又在 yield 前等待 listeners，因此慢 listener 会把背压沿调用链传回 loop，甚至传到 provider stream。

边界判断：run_agent_loop 只定义“事件按什么算法产生”；AgentHarness 决定“谁能启动、状态放哪里、运行中输入如何进入、事件如何向外传播”。

7–10 分钟：三种面试视角

职责

Mechanism vs policy

loop 提供机制：模型调用、工具循环、控制流、事件。harness 提供宿主策略：单飞、取消、队列模式、订阅与跨 run 历史。

测试性

一次 run 可独立验证

测试 loop 时可注入 provider、工具、消息列表和回调，收集事件后断言确定的状态转移；不必建立长期会话对象或模拟 UI 生命周期。

复用性

同一 engine，多种 host

CLI、WebSocket 服务、后台 worker 或测试驱动器可复用同一 loop，但分别选择消息存储、并发控制、断线策略和事件分发方式。

部署边界

进程内对象不是最终平台

Tau 的 harness 是进程内 host。生产平台可以把它的职责拆到 worker、队列、状态存储和事件总线；纯 loop 仍可作为 worker 内核。

不要过度声称：这里的“无状态”是指 loop 不拥有跨 run 的持久状态。它在单次 generator frame 内仍有 turn、pending 等局部状态，也会修改调用者传入的 messages 列表。

10–14 分钟：面试中的 60 秒回答

请不用看答案，回答：

“为什么不直接做一个有状态的 Agent 类，而要把纯 async generator loop 分离出来？”

回答必须包含以下三个词，但不要只是罗列：

  1. 职责
  2. 测试
  3. 部署

控制在 4–6 句话。最好补充一个 trade-off：两层分离带来了什么额外成本？

完成口头回答后，再展开参考结构

我会把单次 run 的确定性状态机放在无状态 loop 中，把消息历史、并发守卫、取消、输入队列和事件订阅放在有状态 harness 中。这样职责清晰：loop 只负责 provider/tool 控制流，host 负责产品生命周期和策略。测试 loop 时可以直接注入 fake provider、工具和回调，收集事件并验证状态转移，不需要搭建完整会话宿主。部署时，同一个 loop 可以运行在 CLI、WebSocket worker 或任务队列消费者中，而 host 层可以替换为进程内对象或分布式状态编排。代价是需要维护两层接口，并明确消息列表的所有权、取消和背压如何跨边界传播。

14–15 分钟：一句话检索

loop 封装单次 run 的 ______，harness 封装跨 run 的 ______；这种拆分让同一核心更容易被不同 ______ 复用。

建议答案关键词：算法/机制、状态/策略、宿主或部署形态。

主来源

src/tau_agent/loop.py:44–168 定义单次 run 的 provider/tool 算法和事件出口；src/tau_agent/harness.py:61–202 定义跨 run 状态、单飞、取消、队列与两个事件出口。行为判断应以这两份项目源码及相应测试为准。
