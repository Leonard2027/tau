没有工具调用时，一轮怎样结束？

这是最简单地理解 loop 出口的机会：while True 怎样开始、模型怎样回复、以及没有工具调用时循环怎样自然结束。

先预测 源码切片 边界练习 完整路线

0–3 分钟：先预测退出路径

你已掌握四层事件与 turn 边界。基于 loop.py:85–166 的循环骨架：

while True:                          # loop.py:85
    has_more_tools = True
    while has_more_tools or pending: # loop.py:87
        ...
        async for event in _assistant_events(...):   # 一次模型调用
            ...
        calls = list(assistant.tool_calls)
        has_more_tools = bool(calls) # loop.py:141
        ...
    follow_ups = ...                 # loop.py:162
    if follow_ups:
        pending = follow_ups
        continue                     # 不 break
    break                            # loop.py:166

纯文本回答（模型没调用工具）时，回答：

  1. has_more_tools 会变成什么？
  2. 内层 while has_more_tools or pending 怎么退出？
  3. 最终 break 怎样触发？

3–10 分钟：读 loop 的前半段与退出路径

src/tau_agent/loop.py:44–85, 158–168

首次 TurnStart 的特殊位置

yield AgentStartEvent()        # loop.py:64
yield TurnStartEvent()         # loop.py:65 —— 循环之外先发一次
for prompt in prompts:
    yield MessageStartEvent / MessageEndEvent

while True:
    ...
    if not first_turn:
        yield TurnStartEvent() # loop.py:88 —— 只有后续 turn 才发
    first_turn = False

first_turn 标志防止第一次循环重复发出 TurnStartEvent。所以最短纯文本序列里那个 TurnStart，来自 loop.py:65。

退出路径不止 break

if assistant.stop_reason in {"error", "aborted"}:   # loop.py:134
    yield TurnEndEvent(message=assistant)
    yield AgentEndEvent(messages=new_messages)
    return                     # ← 提前返回，绕过 break

...
follow_ups = tuple(...)         # loop.py:162
if follow_ups:
    pending = follow_ups
    continue                    # ← 回到外层 while True，开新 turn
break                           # loop.py:166 —— happy path
三条出口：无工具 + 无 follow-up → break；有 follow-up → continue 开新 turn（同一 run 内）；出错/取消 → 提前 return。

10–14 分钟：follow-up 会怎样？

同一 run 内，模型刚给出纯文本回答，你通过 harness.follow_up("等等，换个角度解释") 插入了 follow-up。回答：

  1. break 会立刻触发吗？
  2. 接下来会发什么事件？follow-up 是"接着当前事件发"，还是开启一个新 turn？

用你掌握的 turn 边界解释。

回答后展开参考答案

1. 不会。break 之前会先读 follow-ups（loop.py:162–165）。

2. follow-up 开启一个全新的 turn（新的 TurnStart/End 对），不是"接着当前事件流后面发"。事件流：

... 第一个 turn 结束
TurnStartEvent         ← 新 turn（first_turn 已是 False）
  MessageStartEvent (follow-up 消息)
  MessageEndEvent
  一次新的模型调用……
TurnEndEvent
AgentEndEvent

这就是 UI 层"让 agent 继续想"的体现。

14–15 分钟：一句话检索

没有工具调用时，has_more_tools 变成 ______；内层 while has_more_tools or pending 退出后，没有 follow-up 就 ______；有 follow-up 就回到外层开启 ______；出错则提前 ______。
面试表达：loop 的出口条件把"模型是否要工具"（has_more_tools）和"产品是否追加输入"（follow_ups）解耦为两个判断，各自独立决定循环继续的方向。
