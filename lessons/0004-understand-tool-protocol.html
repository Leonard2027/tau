核心眼中的工具是什么？

工具不只是一个 Python 函数。AgentTool 把模型可见的 schema、运行时 executor、标准结果以及可选的产品层提示组合成一个 provider-neutral 契约。

先预测 源码切片 边界练习 完整路线

0–3 分钟：先拆解一个 read 工具

如果要把本地 read 能力暴露给模型，仅有 async def read(path) 为什么还不够？

先预测核心至少需要哪三类信息：模型怎样知道如何调用、运行时怎样执行、结果怎样回到对话。

3–10 分钟：只读工具契约

src/tau_agent/tools.py:21–105

Model-facing

名字、描述与输入 schema

name、description 和 parameters 告诉模型“有什么工具”以及“arguments 应该长什么样”。input_schema 是 provider payload builder 使用的别名。

Runtime-facing

ToolExecutor

executor 接收 tool_call_id、arguments、取消信号和进度回调，异步返回 AgentToolResult。

Canonical result

AgentToolResult

工具实现返回标准化的 content、details 和可选控制信息。它还是执行结果对象，尚未成为对话历史中的顶层消息。

Optional metadata

提示、参数准备和 renderer

prompt_snippet、prepare_arguments、render_call 等允许产品层增加引导与展示；核心 loop 不直接渲染 UI。

src/tau_agent/loop.py:225–282

执行链

ToolCall(name, id, arguments)
→ 按 name 查找 AgentTool
→ AgentTool.execute(...)
→ AgentToolResult
→ loop 包装成 ToolResultMessage
→ 加入对话历史
两个“result”不要混淆：AgentToolResult 是 executor 的返回值；ToolResultMessage 是 loop 写入消息历史、再发送给模型的顶层记录。
错误隔离：未知工具、被 policy 阻止、取消或 executor 抛出异常，都会被 loop 归一化为错误结果，而不是让厂商模型协议直接看到 Python 异常。

10–14 分钟：把职责放回正确对象

为下面五项选择主要归属：AgentTool、ToolExecutor、AgentToolResult 或 ToolResultMessage。

  1. 向模型声明 path 是必填字符串。
  2. 真正读取磁盘并报告执行进度。
  3. 保存文件内容与字节数等执行详情。
  4. 通过 tool_call_id 进入对话历史。
  5. 提供可选的工具调用展示文本。

14–15 分钟：一句话检索

AgentTool 同时描述模型可见的 ______ 和运行时可调用的 ______；executor 返回 ______，再由 loop 转成 ______。
面试表达：工具契约把 schema、执行与标准结果解耦，使 loop 可以统一调度不同能力，并在边界处完成取消、policy、进度和错误处理。
