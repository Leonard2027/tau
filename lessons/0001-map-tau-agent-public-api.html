Micro lesson 01 · tau_agent · About 15 minutes

tau_agent 对外暴露什么？

今天不进入 loop 的控制流。先把 tau_agent 看成一个库，找出它向使用者提供的几类能力。

预测 源码切片 分类练习 完整路线

0–3 分钟：先预测公共接口

假设你要把 tau_agent 当成库，接到另一个应用里。先写下你认为至少需要哪四类对象。

提示：暂时不要写 Typer、Textual、文件路径或具体模型供应商。

3–10 分钟：只读 __init__.py

src/tau_agent/__init__.py:1–68

不要跳进被导入的文件。只观察 public facade 导出了哪些名字，并尝试分组。

Data

消息与内容

UserMessage、AssistantMessage、ToolResultMessage、content blocks、usage。

Contract

工具与事件

AgentTool、AgentToolResult 与各种 AgentEvent。

Execution

循环与 Harness

run_agent_loop、AgentHarness、配置、取消和 queued messages。

Durability

会话原语

SessionEntry、SessionState、JsonlSessionStorage 等。

观察：tau_agent.__init__ 没有导出 CLI、TUI 或本地 read/bash 实现。这是一个边界信号，而不是遗漏。

10–14 分钟：分类六个对象

把下面对象放进“数据、协议、执行、会话”四组：

AssistantMessage
AgentTool
AgentEndEvent
run_agent_loop
AgentHarness
SessionState

其中某些对象可以有次要角色，但先选择它最主要的角色。

完成后展开参考分类
  • 数据：AssistantMessage
  • 协议：AgentTool、AgentEndEvent
  • 执行：run_agent_loop、AgentHarness
  • 会话：SessionState

14–15 分钟：一句话复述

tau_agent 是一个 provider-neutral 的可复用核心，它对外提供 ______、______、______ 和 ______。
完成标准：能说出四组能力，并指出至少两个刻意不属于该包的产品层概念。今天不要求理解任何实现细节。

下一节：只研究消息模型——一次“用户提问→模型调用工具→工具返回→模型回答”在历史中长什么样。
