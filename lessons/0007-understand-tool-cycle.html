tool result 怎样回到模型上下文？

把消息关联与控制流串起来：模型发出 ToolCall → loop 执行 → 结果 ToolResultMessage 写回历史 → 下一轮模型调用时，这条结果作为上下文的一部分发给 provider。

0–3 分钟：先预测关联与继续

你已掌握消息模型（ToolResultMessage.tool_call_id、AssistantMessage.content 里的 ToolCall.id）与 turn 边界。回答：

  1. 模型发出 read("readme.md") 的 ToolCall 后，ToolResultMessage 凭什么和那个 ToolCall 对上号？
  2. AssistantMessage.stop_reason 是 "toolUse" 还是 "stop" 时，loop 会继续执行工具？
  3. ToolResultMessage 写回 _messages 后，下一轮 provider 凭什么"看到"这条结果？它的 role 是什么？

3–10 分钟：读 tool result 写回历史

src/tau_agent/messages.py:77–85, 170–193

关联字段

ToolCall.id ↔ ToolResultMessage.tool_call_id

执行时 loop 把 call.id 原样写进结果消息。provider 端靠这一对 id 把"请求"与"结果"配成一组 tool-use 回合。

Role 是 provider 看的

role: "toolResult"

ToolResultMessage.role 是 provider 识别"这是工具结果"的依据。它与 "user"/"assistant" 并列，构成模型上下文的基本角色。

src/tau_agent/loop.py:139–157, 225–282

写回动作发生在哪

calls = list(assistant.tool_calls)
has_more_tools = bool(calls)              # loop.py:141
for call in calls:
    async for event in _execute_tool_call(...):   # loop.py:143
        yield event
        if isinstance(event, MessageEndEvent) and isinstance(
            event.message, ToolResultMessage
        ):
            tool_results.append(event.message)     # 本 turn 的结果列表
            messages.append(event.message)         # 写回持久历史
            new_messages.append(event.message)     # 写回本次 run 的 delta

关键：_execute_tool_call 在 loop.py:273–282 构造 ToolResultMessage(tool_call_id=call.id, ...) 并发出 MessageStart/EndEvent；loop 捕获后追加到 messages（持久历史）。下一轮 _provider_context(messages) 会把它作为上下文传给 provider。

结果为什么能"回到"模型上下文：不是 provider 主动去查，而是 loop 把结果 append 到 messages，下一次 stream_response(messages=...) 时结果自然携带进去。tool_call_id == ToolCall.id 让 provider/adapter 把它组装成工具回复的协议形态。

10–14 分钟：模拟一次 read 的两轮对话

用户："帮我读 readme.md"。模拟两次模型调用（两个 turn）的完整消息历史与事件流。

写出每一条 messages 里的顶层记录（role + 关键字段），并标注 has_more_tools 在两个 turn 后各是什么。

回答后展开参考答案 
Turn 1:
  messages 追加: AssistantMessage(role=assistant, content=[ToolCall(id="c1", name="read", arguments={path:...})], stop_reason="toolUse")
  has_more_tools = True (因为 calls 非空)
  → 执行 read, 追加 ToolResultMessage(role=toolResult, tool_call_id="c1", tool_name="read", content=[文件内容], is_error=False)

Turn 2:
  下一轮 _provider_context 携带上述两条 + 用户消息
  → 模型看到文件内容, 回复 AssistantMessage(role=assistant, content=[TextContent(总结)], stop_reason="stop")
  has_more_tools = False
  → 无更多工具, 无 follow-up → break → AgentEndEvent

关联链：模型请求（c1）→ 执行 → 结果（tool_call_id=c1）→ 下一轮模型看到文件内容并给出总结。

14–15 分钟：一句话检索

ToolResultMessage 通过 ______ 与 ToolCall 对上号；写回 messages 后，下一轮 provider 靠它的 ______ 字段识别"这是工具结果"，从而把它作为 ______ 的一部分。has_more_tools 由 assistant 的 ______ 决定。
面试表达：工具结果"回到"模型上下文不是靠特殊通道，而是作为一条普通的历史消息（role=toolResult）被追加，下一次请求时自然携带。请求-结果配对靠 tool_call_id == ToolCall.id 维持，这是 agent 平台保证对话协议完整的核心机制。
