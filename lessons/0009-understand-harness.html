AgentHarness 比裸 loop 多了什么？

loop 是无状态的 async generator；harness 是有状态的主机，负责把 run 的生命周期、输入队列、消息历史编排起来，并向外暴露事件与状态。

先预测 源码切片 状态练习 完整路线

0–3 分钟：先预测状态归属

run_agent_loop(...) 接收 messages、tools、prompts、get_steering_messages、get_follow_up_messages 等参数，是一个纯 async generator——它本身不持有跨 run 的状态。

如果产品要支持"一次对话跨多个 run（多次 prompt）"、运行中插入 steering/follow-up、以及取消，这些状态必须放在 loop 之外。猜猜 AgentHarness 至少要保存哪几类状态？

提示：三个词——生命周期、队列、消息历史。

3–10 分钟：读 harness 的状态字段与入口

src/tau_agent/harness.py:61–100, 146–217

生命周期

running / signal / listeners

_running 标记单飞；_current_signal 是取消令牌（SimpleCancellationToken）；_listeners 是订阅者列表。prompt/continue_ 入口保证同一时刻只有一个 run。

队列

steering / follow-up

_steering_queue、_follow_up_queue 在 run 进行中接收插话，queue_mode 决定一次取一条还是全部。这些是消息注入语义，不是并行任务。

消息历史

_messages

harness 持有跨 run 的完整对话历史。loop 每次 run 都往它追加，provider 下一次调用时作为上下文携带。

入口如何启动一个 run

def prompt_message(self, message):
    self._ensure_not_running()          # 单飞守卫
    self._append_interrupted_tool_results()   # 修复孤儿工具调用
    self._running = True
    return self._run(prompts=(message,))

async def _run(self, *, prompts=()):
    signal = SimpleCancellationToken()
    self._current_signal = signal
    try:
        async for event in run_agent_loop(
            messages=self._messages,     # harness 持有的历史
            prompts=prompts,
            get_steering_messages=self._drain_steering_messages,
            get_follow_up_messages=self._drain_follow_up_messages,
            ...
        ):
            await self._notify(event)    # 通知所有 listener
            yield event
    finally:
        self._running = False
分工：loop 只做"纯算法"（模型调用、工具调度、事件产出）；harness 负责"有状态编排"（何时允许跑、如何注入输入、把事件广播给谁）。同一个 loop 可以被不同 host 复用，只需各自提供状态。

10–14 分钟：区分算法状态、生命周期和消息队列

把下面每一项归到 loop（纯算法） 或 harness（状态编排）：

  1. turn 计数器、has_more_tools
  2. _running 单飞守卫
  3. _steering_queue / _follow_up_queue
  4. 把 assistant 结果 append 到 messages
  5. 取消令牌 SimpleCancellationToken
回答后展开参考答案
  1. loop —— 单次 run 内的纯算法变量，run 结束即消失。
  2. harness —— 跨 run 的生命周期状态。
  3. harness —— 跨 run 的输入队列。
  4. loop —— 它把结果写进传入的 messages 列表；harness 只是持有该列表。
  5. harness —— 它创建并传给 loop，loop 只读 signal.is_cancelled()。

判断标准：状态是否跨 run 存续。只在单次 run 内有效 → loop；需要在下一次 run 仍存在 → harness。

14–15 分钟：一句话检索

run_agent_loop 是 ______（无状态/有状态）的 async generator，AgentHarness 是它的 ______（无状态/有状态）主机；harness 负责 ______ 生命周期、______ 队列和 ______ 消息历史。
面试表达：把"算法"与"状态编排"分开，使纯 loop 可复用、可测试，同时让 harness 集中处理并发、取消、队列注入与事件广播——这是 agent 平台常见的"core engine + host/container"分层。
