The strongest correction this card: the learner initially said "the tool result is appended in turn 2". In fact the ToolResultMessage is written back within Turn 1 (immediately after executing the tool produced by that turn), collected into that turn's TurnEndEvent.tool_results; Turn 2's model call simply sees the result already lying in the message history passed to the provider. This nails the precise answer to "how does a tool result return to model context": not via a special channel, but as an ordinary history message (role=toolResult) appended during the producing turn and carried into the next request. They also confirmed has_more_tools = bool(calls) is about presence of tool calls, not count (2 ToolCalls → tool_results has 2 entries, has_more_tools still just True).
